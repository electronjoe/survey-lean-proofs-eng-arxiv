# Human Annotations & Inter-Rater Reliability (IRR)

This directory stores version-controlled, license-safe human verification records used to calibrate and validate the automated LLM-as-a-judge stages (Stage 4 classification and Stage 5 Layer-A semantic fidelity audits).

## Planned Files & Schemas

### 1. `stage4_irr.csv` (Stage 4 Classification Calibration)
Independent human labels on a blinded stratified sample (`n = 30`, generated by `scripts/prepare_stage4_irr.py --seed 20261123` into `stage4_irr_blank.csv`, the offline interactive HTML walkthrough `docs/stage4_irr_walkthrough.html`, and gitignored `data/stage4_irr_dossier.md`) compared against `artifacts/slices/<slice_id>/classifications.json` via `scripts/compute_irr.py` for Cohen's $\kappa$, Krippendorff's $\alpha$, and confusion matrices:

```csv
slice_id,arxiv_id,annotator_id,lean_usage_status,paper_domain_role,authoring_paradigm,verification_tier,ai_agent_assisted,notes
```

#### Stage-4 Enum Cheat-Sheet (exact strings from `workflows/classify_candidates.py`)

Zero Lean code reading is required—judge solely from title, abstract, categories, Stage-2 prose snippets, README excerpts, and Stage-3 static counts. For non-contributed papers (`lean_citation_or_discussion` or `false_positive`), set the remaining four label columns to `N/A`.

| Column | Allowed Values | Concise Coding Rule |
| :--- | :--- | :--- |
| `lean_usage_status` | `lean_contributed` · `lean_citation_or_discussion` · `false_positive` | `lean_contributed`: authors formalize/verify their own paper's theorems or artifacts in Lean. `lean_citation_or_discussion`: cites/discusses Lean/Mathlib or evaluates LLM-prover benchmarks without formalizing this paper's own theorems. `false_positive`: non-ITP usage of "lean" (lean manufacturing/architecture/body mass/etc.). |
| `paper_domain_role` | `engineering_math_proof` · `software_or_system_fv` · `pure_tcs_or_math` · `N/A` | `engineering_math_proof`: math theorems in engineering/applied theory (control, sysID, comms/coding/info theory, signal processing, optimization, networks, statistical/ML theory, crypto math). `software_or_system_fv`: verifies an implementation, policy engine, VM, DB/pipeline, distributed protocol, or hardware. `pure_tcs_or_math`: pure TCS (complexity/graphs/CONGEST) or pure math cross-listed into engineering. |
| `authoring_paradigm` | `P1_paper_first_posthoc` · `P2_lean_first` · `P3_blueprint_sync` · `P4_speclock_solve_distill` · `P0_opaque_or_unspecified` · `N/A` | `P1`: informal paper/proofs first, Lean formalization added post-hoc or loosely attached. `P2`: Lean proof developed first, paper written/auto-informalized from Lean. `P3`: synchronized co-development via `leanblueprint` / `LeanArchitect` (`@[blueprint]`, `\inputleannode`) / Verso Blueprints. `P4`: frozen `Challenge.lean`/`Solution.lean` or `comparator` spec-lock, unconstrained search, then conceptual distillation into paper. `P0`: claims Lean verification of own results, but no public Lean code and insufficient workflow detail. |
| `verification_tier` | `Tier3_Gold` · `Tier2_Silver` · `Tier1_Bronze` · `N/A` | `Tier3_Gold`: public Lean repo for main theorem(s), `sorry=0`/`custom_axiom=0`/`native_decide=0`, AND spec/kernel audit evidence (blueprint sync, `comparator`, multi-kernel/`leanchecker`, `#print axioms`, or explicit audit manifest/CI). `Tier2_Silver`: public compiling-looking Lean repo (0 `sorry`/axiom or minor gaps), partial/supporting lemmas or standard `lake build` without comparator/multi-kernel/blueprint sync. `Tier1_Bronze`: claimed Lean without public artifact, OR contains `sorry`/custom `axiom`/`native_decide`, OR unchecked agent-only dump. |
| `ai_agent_assisted` | `explicitly_yes` · `explicitly_no` · `unclear` · `N/A` | `explicitly_yes`: paper/README/LaTeX explicitly credits LLM/AI coding/proving agents (e.g., Claude, Codex, Gemini, GPT, Aristotle, DeepSeek) for Lean formalization or proof search. `explicitly_no`: paper/README explicitly states human-written / no AI assistance. `unclear`: `lean_contributed` with no clear disclosure either way. |
