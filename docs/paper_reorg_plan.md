## 1. Executive Summary & Goal

As the study evolved iteratively—from a 6-category T2 pilot (`v0.1`), to an 8-category T2 snapshot (`v0.2`), to 3-slice longitudinal backfills (`v0.4`), compact Docker kernel verification (`v0.5`), blinded human IRR (`v0.6`), and finally a 4-way role taxonomy, `+7` engineering category expansion (`15` categories total, including `100%` of `eess.*`), operational-FV boundary audit, and off-arXiv bibliometric probe (`v0.7`)—each milestone was **layered onto `main.tex` as incremental subsections and companion tables** rather than replacing superseded 8-category / 3-way exposition.

**Goal:** Reorganize and rewrite [`papers/arxiv-empirical/main.tex`](../papers/arxiv-empirical/main.tex) so that **the entire study is presented consistently from Page 1 to the Appendix as one cohesive paper** built around:
1. **One primary corpus:** The **15-category whole-category census** across three matched 19-day windows (`T0: Nov 1–19, 2025`, `T1: May 1–19, 2026`, `T2: Nov 1–19, 2026`; **$N = 12{,}613$ unique preprints**, covering **100% of arXiv's `eess.*` archive**).
2. **One primary classification taxonomy:** The deterministic **4-way role taxonomy** (`eng_algorithmic_proof`, `operational_system_fv`, `pure_math_or_tcs`, `meta_formalization_system`), with **`eng_algorithmic_proof`** explicitly defined up front as our core object of study and the other three roles retained in whole-category totals as transparent contrast/boundary strata.
3. **Zero archaeological scaffolding:** Eliminate `"Pilot v1"`, `"Pilot v2"`, `"orig-8"`, `"+7 expansion"`, `"Phase C1/C2/D1"`, dual parenthetical statistics in prose, split `"orig-8 vs. +7"` tables, and `[+7]` badges in figures.
4. **Scholarly paper register (not a pipeline technical report):** Replace all raw JSON schema enum strings (`eng_algorithmic_proof`, `material_undisclosed_drift_or_risk`, `Tier3_Gold`, `v_latest`, `explicitly_yes`, etc.) with natural academic English across prose, tables, and figure legends; strip internal repo paths (`src/*.py`, `artifacts/*.json`), CLI flags, and regex bug-fix logs from narrative and captions into a single *Data & Code Availability* subsection / Appendix; and cut the Abstract from ~680 words (`60+` bold spans) to a crisp ~250-word scholarly abstract.

**Bottom-Line Feasibility Verdict:** **There are ZERO fundamental scientific or data-collection blockers.** Every paper across all 15 categories and all 3 temporal slices has already completed OAI-PMH ingestion, full-text screening (`99.61%`), static artifact profiling, 4-way role classification, `v1`-vs.-`v_latest` verification, and exhaustive Stage-5 Layer-A + compact Docker kernel verification over 100% of inspectable `eng_algorithmic_proof` repositories. There are, however, **7 concrete structural, data-harmonization, and cohort-boundary barriers** (detailed in Section 3 below)—all of which have clean, low-cost resolutions.

## 5. Academic Prose & De-Jargoning Guide (Eliminating "Code Technical Report" Style)

To make [`papers/arxiv-empirical/main.tex`](../papers/arxiv-empirical/main.tex) read like an archival empirical research paper (e.g., *CACM*, *EMSE*, *ACM TOSEM*, *ITP*) rather than an internal software specification, the rewrite will enforce five style rules across **all prose, tables, and matplotlib figures**:

### 5.1 Zero Raw `snake_case` / `CamelCase` JSON Enum Values in Prose, Tables, or Figures

Internal JSON schema keys stay strictly inside `artifacts/*.json` and `scripts/*.py`. Everywhere in `main.tex` and `src/generate_figures.py`, replace verbatim enum strings with clean, consistent English terms:

| Internal JSON / Code Token | Clean Academic Term in Paper & Figures | Acceptable Compact Table Shorthand |
| :--- | :--- | :--- |
| `eng_algorithmic_proof` | **Engineering algorithmic proofs** *(or* **Engineering theory proofs***)* | `Eng. Alg.` |
| `operational_system_fv` | **Operational system verification** | `System FV` |
| `pure_math_or_tcs` | **Pure math & theoretical CS** *(cross-lists)* | `Math / TCS` |
| `meta_formalization_system` | **Autoformalization pipelines** *(or* **Meta-formalization systems***)* | `Meta-System` |
| `lean_usage_status` / `lean_contributed` | **Lean proof contribution** *(contributing vs. citing/discussing Lean)* | — |
| `v1` vs. `v_latest` / `v_lat` / `P1-retro` | **Initial submission (`v1`)** vs. **Latest revision** / **Retroactive formalization** | `Initial (v1)` / `With Rev.` |
| `Tier3_Gold`, `Tier2_Silver`, `Tier1_Bronze` | **Gold**, **Silver**, and **Bronze** verification tiers | `Gold` / `Silver` / `Bronze` |
| `P1_paper_first_posthoc` … `P4_speclock_solve_distill`, `P0_opaque_or_unspecified` | **Post-hoc formalization (`P1`)**, **Lean-first (`P2`)**, **Synchronized blueprint (`P3`)**, **Pinned specification (`P4`)**, **Unspecified (`P0`)** | `P1 (Post-hoc)` … `P4 (Spec-lock)` |

### 5.2 Strip Internal File Paths, Script Names & Bug Logs from Narrative and Captions
- **Zero repo paths in captions or narrative:** Remove all inline `\texttt{src/...}`, `\texttt{scripts/...}`, `\texttt{workflows/...}`, `\texttt{data/*.db}`, `\texttt{reports/...}`, and `\texttt{artifacts/*.json}` strings from Abstract, main sections, and table/figure captions. Consolidate repository structure and replication pointers into **one concise *Data & Code Availability* paragraph** at the end of the paper.

Keep only the substantive methodological insight (e.g., why zero-dependency system models should not be penalized for omitting Mathlib).

### 5.3 Move Low-Level Infrastructure Plumbing Out of Main Prose
- **Methodology (Section 3) & Sandbox (Section 6):** Describe the pipeline and clean-room container guarantees at the **conceptual and threat-model level** in main prose (e.g., *"compiled offline in an unprivileged, read-only container with pre-cached toolchains, followed by kernel-level transitive axiom collection across all exported theorems"*). - **Code & commit citations (`file:line`, Git SHAs):** Keep exact Lean declaration names where mathematically illuminating, but move raw commit hashes and multi-segment file paths (`TheoremLib/.../items/thm_1.lean:1495-1520`) into footnotes or compact summary tables so prose sentences read smoothly.

### 5.4 Abstract Compression & Visual De-Cluttering
- **Abstract target: ~230–260 words, ZERO boldface (`\textbf`), ZERO `\texttt` enums/internals:** Written for a broad engineering and formal-methods audience—stating the research question, the 12,613-paper 15-category longitudinal design, the headline adoption surge vs. traditional formal tools, the 4-way disciplinary finding, the semantic-fidelity contrast between author-owned repos and bulk autoformalization, the clean-room build rate, and the operational-FV boundary.
